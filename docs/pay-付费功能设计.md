# 「短句」付费功能设计（Phase 0）

> 决策基线（2026-11-18 确认）：**订阅制**（月卡 / 年卡 / 终身，均为一次性购买，**一期不做自动续费**）；
> 首发付费点 = **AI 私教增强**（含在会员权益内）。全部改动遵循后端/前端既有约定
> （schema 同 PR 补迁移 + `docs:gen`；金额一律服务端定价；单测只跑与改动相关部分）。

## 1. 产品层设计

### 1.1 定价与 SKU（服务端定价，客户端只传 SKU code）

| code           | 名称     | 价格             | 有效期 |
| -------------- | -------- | ---------------- | ------ |
| `vip_month`    | 会员月卡 | ¥12（1200 分）   | 30 天  |
| `vip_year`     | 会员年卡 | ¥68（6800 分）   | 365 天 |
| `vip_lifetime` | 终身会员 | ¥128（12800 分） | 永久   |

- SKU 落表（`pay_sku`，启动幂等种子，后台可改价后即时生效，不随发版）。
- 权益只认 `kind='vip'`：到期即失效；终身卡 `expires_at` 为 NULL。
- **不发连续包月**：国内自动续费合规成本高（提前 5 天提醒、显著同意、随时可退），一期完全规避。

### 1.2 权益口径（免费层一寸不动）

| 能力                                | 免费                              | 会员（vip）                                |
| ----------------------------------- | --------------------------------- | ------------------------------------------ |
| 每日刷题 / 打卡 / 排行榜 / 基础成就 | 完整                              | 完整                                       |
| AI 造句 / 词根 / 私教点评           | `AI_DAILY_QUOTA`（默认 50 次/日） | `PAY_VIP_AI_DAILY_QUOTA`（默认 200 次/日） |

- 付费墙**只放在「量」上**：每日 20 句、打卡、排行榜永不受限。
- 付费判断全收敛到 `EntitlementService.isVip(userId)`；AI 配额在
  `AiQuotaService.resolveLimit` 里分档（当日升级、当日剩余额度即变大，不改计数键）。

## 2. 技术方案

### 2.1 渠道与下单方式（`node:crypto` + `fetch`；唯一新增依赖 `qr-image`）

| 端               | 微信支付 API | 说明                                                                          |
| ---------------- | ------------ | ----------------------------------------------------------------------------- |
| Web（PC 收银台） | Native 下单  | 返回 `code_url`，前端渲染二维码，用户手机微信扫码                             |
| Android          | Native 下单  | 同 Web：页内展示二维码 + 保存/分享（复用句签 ShareBridge，零新依赖）          |
| 小程序           | JSAPI 下单   | `payer.openid`（复用 `wx.login` 链路），返回 `paySign` 给 `wx.requestPayment` |

- 不做 APP 支付 / H5 支付：需要额外商户权限与包名/签名绑定，二维码方案覆盖 Android 且零成本。
- 二维码统一由服务端用零依赖的 `qr-image` 生成（PNG → data URL），Web 用 `<img>`、Android 用
  `Image.memory`，两端都不引二维码库；`code_url` 同时下发便于排障。
- **iOS 微信内**：小程序 iOS 端虚拟支付受苹果政策限制，购买入口按 `systemInfo.platform` 隐藏并引导 Web/Android。

### 2.2 数据模型（`api/prisma/schema/pay.prisma`）

```
pay_sku              SKU 定义（code 唯一、价格=分、durationDays=0 终身）
pay_order            订单：orderNo 唯一、状态机 pending→paid→refunded｜closed
pay_callback_log     回调流水：验签结果 + 解密明文（对账/排障/幂等依据）
user_entitlement     权益：kind=vip、expiresAt=NULL 终身、status active/revoked
```

订单状态机：

```
pending ──支付成功回调──▶ paid ──后台退款──▶ refunded（同步撤销权益）
   └──── 30 分钟未支付 ───▶ closed
```

- `orderNo` 服务端生成（`SS` + 时间 + 随机），唯一索引兜幂等；
- 金额**只从 `pay_sku` 读**，客户端传 `skuCode` + `channel`，不传价格；
- 回调先验签（平台证书 RSA-SHA256）→ 解密（AES-256-GCM，apiv3 key）→ 校验金额/订单归属 →
  状态机推进（已 paid 的重复回调直接 ACK，不重复发权益）→ 写 `pay_callback_log`。

### 2.3 安全要点

| 项      | 口径                                                                                                                                                 |
| ------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| 验签    | 请求头 `Wechatpay-Signature/Timestamp/Nonce/Serial` + **rawBody**；平台证书 `GET /v3/certificates` 拉取、按序列号内存缓存                            |
| 防重放  | 验签时间戳与本地误差 ≤5 分钟；`transaction_id` + `orderNo` 双幂等                                                                                    |
| 金额    | 回调明文里的 `amount.total` 必须等于订单金额，否则拒收并告警                                                                                         |
| 密钥    | 商户私钥 / APIv3 密钥存 `sys_config`（后台「支付设置」维护，读接口只回掩码），env 兜底；缺失时支付功能整体禁用、**不阻断启动**（与 AI/微信同一口径） |
| rawBody | `app.setup.ts` 的 json body parser 加 `verify` stash（2MB 上限不变），仅验签用                                                                       |

### 2.4 密钥清单（用户在后台「支付设置」填入）

`appid`（JSAPI=小程序 appid，Native=同商户下任意已绑定 appid）/ `mchid` / 商户证书序列号 /
商户 API 私钥（`apiclient_key.pem`）/ APIv3 密钥（32 位）/ 回调地址（`https://<域名>/api/pay/notify/wechat`）。

## 2.5 安全清单（已实现，评审时可逐条对照）

| 面             | 措施                                                                                                                                        |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| 回调真实性     | 平台证书 RSA-SHA256 验签（rawBody 原文）+ 时间戳 5 分钟防重放；缺头请求直接拒且不落库                                                       |
| 回调归属       | 解密后再校验 `mchid` / `appid` 必须与后台配置一致（平台证书全商户共用，验签通过 ≠ 属于本商户）                                              |
| 回调金额       | `amount.total` 必须等于订单金额、`currency` 只接受 CNY、必须为正整数；不符回 400 并留痕                                                     |
| 幂等           | 订单状态用 `updateMany` 条件更新推进；重复通知只 ACK 不重复发权益                                                                           |
| 退款并发       | `paid → refunding` 抢占式更新，失败回滚为 `paid`；重复点击不会发第二笔退款                                                                  |
| 部分退款       | 只认全额退款通知；部分退款不动会员权益（避免运营手工部分退款导致误撤）                                                                      |
| 定价           | 客户端只传 `skuCode`，金额一律查库；价格 ≤0 拒绝下单                                                                                        |
| 防刷           | 单用户待支付订单上限 5 笔；订单状态轮询查微信按订单 5 秒节流；回调缺头不写流水                                                              |
| 密钥存放       | `sys_config` 明文存库（调用需读），读写都走专属接口；**通用参数接口**对 `pay.wechat.*` / `mail.ses.*` 一律隐藏/拒绝，避免只读管理员越权读取 |
| 日志           | 操作日志递归脱敏：`privateKey` / `apiv3Key` / `apiKey` / `secretKey` / `password` / 各类 token / 一次性验证码（兼容 snake_case 与全大写）   |
| 私钥文件       | 允许填路径，但只允许读**项目根目录内**的 `.pem/.key`，越界直接判为不可用                                                                    |
| 客户端可见数据 | 「我的订单」剔除 `refundReason` / `refundId` 等运营内部字段；错误只回通用文案，细节进服务端日志                                             |
| 留存           | 回调流水保留 180 天后分批清理（含 payer openid 等 PII）                                                                                     |
| 配置自检       | 后台「测试连接」拉平台证书并用 APIv3 密钥解密，验证私钥/密钥是否正确（无资金动作，可反复点）                                                |
